# 输入处理规则（input-parsing）

本文件规定 skill 如何把用户给的「材料」变成可锻造的结构化概念。

## 1. 支持的输入与摄取方式

| 输入类型 | 怎么读 | 备注 |
|---|---|---|
| 粘贴的大段文字 | 直接用，无需读文件 | 最常见；可能是微信/网页/笔记复制来的 |
| `.txt` / `.md` | `Read` 工具直接读 | 纯文本，最干净 |
| `.docx` | 调 `markitdown-skill` 转成 Markdown 再读 | 保留标题层级，利于抽概念 |
| `.pdf` | 先 `Read`（能解析则直接读）；失败退回 `markitdown-skill` | 扫描版 PDF 可能抽不出字，需提示用户 |
| 多份文件 | 全部摄取后合并去重 | 在「概念解析」阶段统一去重，避免同一概念出多张卡 |

> 注意：`Read` 对 PDF 是逐页抽取，长 PDF 注意分段；`markitdown-skill` 是仓库内已装 skill，用自然语言让它「把 xxx.docx 转成 markdown」。

## 2. 分段（chunk）策略

材料过长（单份 > ~4000 字，或明显是多个章节）时：

1. 先按天然边界切：标题层级（# / 章节）、空行分段、列表块。
2. 每段独立抽取概念，再跨段合并：同名概念合并、互补信息合并进同一张卡片。
3. 概念数量上限：**单份材料建议 20–30 个概念**。超过则先问用户「重点看哪几块」，或按信息密度自动取舍（保留定义性 + 高频出现的概念）。

## 3. 概念抽取启发式

对每段，产出概念候选：

- **显式术语**：标题、加粗、专有名词、定义句式（「X 是……」「所谓 X」「X 指」）。
- **流程 / 步骤**：出现「第一步 / 然后 / 最后」「流程」「步骤」→ 抽成流程类概念（需 worked example）。
- **清单 / 枚举**：出现「包括 A、B、C」「三大 / 五项」→ 抽成清单类概念（需用口诀 / 分组块）。
- **对比 / 关系**：出现「A 与 B 的区别」「A 包含 B」→ 抽成对比 / 层级概念（用对比图 / 脑图）。

## 4. 熟悉度判断（决定是否联网深潜）

对每个概念，标一个熟悉度：

- **熟悉**：材料已讲清 + 属于常识 / 用户领域内的词 → 不出网，直接锻造。
- **半熟**：材料提了但讲得浅，或用户领域外但常识内能解释 → 可补一句类比，不出网。
- **需深潜**：材料没讲清、或明显是用户不熟的术语（如用户给的是前端资料却不懂「DOM」「事件委托」）→ 标 `web_deepdive: true`，走 `references/web-deepdive.md`。

判断信号：概念在材料里只出现名词没解释；术语跨领域（材料是 A 领域却出现 B 领域词）；用户口头说「这个我不懂」。

## 5. 概念间关系（给脑图用）

抽取同时记录父子 / 兄弟关系：

- 层级：X 包含 Y → X 是父，Y 是子。
- 并列：同属一个分类下的多个概念 → 共父。
- 流程：A→B→C 顺序 → 用有向连接或同父下的顺序子节点。

脑图根节点用材料的主题名（如「前端核心」「中心荣誉与资质」）。

## 6. 缺信息时的追问（最多一轮，≤5 问）

信息不足先问，别硬做：

1. 受众基础（小白 / 进阶）？—— 决定类比密度与铺垫量。
2. 是否需要导出学习包？—— 默认是。
3. 输出语言？—— 默认中文。
4. 有没有重点章节 / 必须记住的？—— 没有就全量锻。
5. 材料主题 / 这份资料用来干嘛（考试 / 汇报 / 科普）？—— 决定语气与详略。

基础信息（受众、是否导出、语言）给默认值即可，不强制问；真正卡住时才问。
