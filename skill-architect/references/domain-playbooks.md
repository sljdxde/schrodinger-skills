# Domain Knowledge Engine — 领域补全库

作用：**帮用户发现未知需求**。用户说「我要旅游助手」时，系统自动提醒「旅游可能涉及：行程规划、预算控制、酒店选择、交通安排、风险管理」。

用法：Path A 第二阶段直接调用对应清单；新领域用文末「通用模板」现场生成。清单是**起点**不是终点——永远以「该领域通常包含什么」开场，再让用户增删。

---

## 学习助手（Study）

- 概念拆解：把材料拆成可独立理解的单元
- 记忆规划：间隔复习（艾宾浩斯/SM-2）排程
- 自测与错题：先答后揭晓，错题归因
- 学习路径：按目标排课程/资料优先级
- 进度追踪：掌握度可视化与下一步建议
- 检索补充：陌生术语的权威解释与来源标注

## 旅行助手（Travel）

- 行程规划：按天数/偏好排景点动线
- 预算控制：总预算分摊到交通/住宿/门票/餐饮
- 酒店选择：位置/价格/评分多目标权衡
- 交通安排：城际与市内交通衔接、预订提示
- 风险管理：签证、保险、天气、安全提示
- 行前清单：证件/物品/预订确认的 checklist

## 投资助手（Investment）

- 风险画像：风险承受能力评估
- 资产配置：按目标与期限分配大类资产
- 标的研究：对具体标的做多维度分析
- 成本与税费：费率、税负、持有成本
- 再平衡：偏离阈值与调仓规则
- 复盘：定期回顾与偏差归因

## 创作助手（Creation）

- 选题：从素材/趋势中提炼可写选题
- 结构设计：开头-主体-收尾的骨架
- 风格校准：目标读者与语调设定
- 迭代反馈：草稿的修改清单与评审
- 发布运营：平台适配与分发节奏

---

## 通用领域模板（新领域用这个现场生成）

对任何新领域，按以下 7 问生成能力清单：

1. **目标**：这个 Skill 最终帮用户达成什么？（一句话）
2. **核心任务**：拆出 3–8 个叶子任务，每个任务一句话。
3. **能力清单**：每个任务展开成 1–3 条可独立验证的能力。
4. **数据需求**：每个能力需要什么输入数据/信息来源？
5. **判断标准**：做判断时的依据或阈值（没有就标「待访谈提取」）。
6. **输出形式**：报告 / 打分 / 建议 / 流程 / 清单？
7. **边界**：哪些明显相关但**不该**由本 Skill 做？

生成后回到 Interview Engine 第二阶段，把清单交给用户勾选。

---

## 质量要求

- 清单项必须**可验证**（能设计测试任务），不要「提供优质建议」这种空话。
- 每个能力一句话说清「输入 → 动作 → 输出」。
- 领域清单里的判断标准尽量给阈值/规则雏形（如「偏离 5% 触发再平衡」），给不了就标「待 Path B 访谈提取」。
