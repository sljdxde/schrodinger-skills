# ADR-0004 反爬取数通道与合规边界

- 状态：已采纳（Accepted）
- 日期：2026-08-11

## 背景 (Context)

贝壳 / 我爱我家等网页源有 UA 校验、Cookie/登录态、JS 渲染、接口签名等反爬；杭房数研 / 小鸡选房等小程序是封闭生态，无公开网页 API。用户要求"这些有反爬虫策略，你需要能够绕过"。

## 决策 (Decision)

维持**三通道**依次降级（已在 `data_sources.py` 实现）：

1. **抓包 API（优先）**：用户用 mitmproxy / Charles 抓小程序，或从 DevTools 拿网页源公开接口，写入 `sources.json`。脚本直连。
2. **浏览器渲染（兜底）**：配置 `browser:true` + cookie/headers，必要时本机 Playwright 渲染公开页面再解析。
3. **联网检索（默认兜底）**：未配置时脚本生成精确到数据源与城市的检索式，由 AI 代理 WebSearch/WebFetch 回填。

**合规边界（硬性）**：

- 只处理**公开页面 / 公开公示数据**；不绕过登录墙获取非公开数据。
- 不破解验证码、不伪造身份规避平台封禁。
- 不短时间高频批量抓取；网页源 `request_interval ≥ 1s`。
- 政府公开源 / 政务 APP 的**公示类**数据优先；政务 APP 深层数据需用户授权后抓包，不擅自突破。

## 后果 (Consequences)

- "绕过"指合规地用浏览器化请求 / 抓包读取公开数据，而非攻击式破解——能力边界清晰、可持续。
- 小程序源天生依赖用户一次性抓包，无法全自动化；注册表（ADR-0001）只登记名称与抓包提示。

## 备选 (Alternatives)

- 引入无头浏览器高频爬取：违规且易封，否决。
- 购买第三方数据 API：成本与合规不确定，暂不在 scope。
