# ADR-0001 全国城市源注册表（预置内置）

- 状态：已采纳（Proposed → Accepted）
- 日期：2026-08-11

## 背景 (Context)

用户要求：分析全国房源时，"先把全国省会 + 自治区首府 + 直辖市的相关信息源内置好，避免使用的时候再去检索"。当前脚本仅内置杭州双小程序（杭房数研 / 小鸡选房）+ 贝壳 / 我爱我家（全国网页源），其余城市运行时靠 WebSearch 兜底，慢且不稳。

## 决策 (Decision)

预置 **城市源注册表**，覆盖约 31 城：

- 直辖市（4）：北京、上海、天津、重庆
- 省会 / 自治区首府（27）：石家庄、太原、沈阳、长春、哈尔滨、南京、杭州、合肥、福州、南昌、济南、郑州、武汉、长沙、广州、南宁、海口、成都、贵阳、昆明、拉萨、西安、兰州、西宁、银川、乌鲁木齐、呼和浩特

每城登记四类信息源：

1. **全国网页源**：贝壳 / 我爱我家——已内置，按城市选 endpoint。
2. **政府公开源**：该城住建 / 网签 / 二手房公示平台（多为无需登录的公开数据）。
3. **政务 APP**：该省政务服务 App（浙里办类）+ 其不动产 / 住房板块入口。
4. **本地小程序**：该城若有高价值封闭生态房源源（如杭州杭房数研 / 小鸡选房），登记名称与抓包提示。

注册表写入 `scripts/city_sources.json`（结构：`{城市: {gov:[...], gov_app:[...], mini_program:[...], note}}`），脚本 `load_sources(city)` 在选源时优先命中注册表里的政府源 / 政务 APP 名称，生成精确检索式或直连配置。

## 后果 (Consequences)

- 运行时对 31 城无需临时检索即可给出"去哪查"的明确指引，提速且更稳。
- 政府源 URL 易变：注册表**只存平台名 + 官方入口关键词 + 取数方式提示**，不硬编码易失效的深层 API；深层 API 仍靠用户抓包填入 `sources.json`。
- 维护成本上升：需随政策 / 平台变更更新注册表（纳入 `update_self.py` 的远程同步范围）。

## 备选 (Alternatives)

- 仅依赖贝壳 / 我爱我家 + 检索兜底（不做注册表）：实现轻，但用户明确否决。
- 硬编码各城政府深层 API：最稳但维护灾难且易违规，否决。
