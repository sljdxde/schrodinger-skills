# Data Source Playbook

本文件用于执行购房分析的数据采集。城市由用户声明，覆盖全国房源；采集时优先找原始来源，多源交叉验证，最后用证据台账承载不确定性。

## 证据台账

每条关键结论都用这 7 列自查：

| 字段 | 写法 |
|---|---|
| 事实/数据 | 例如“近一年主力成交单价约 X 万/㎡，月度时间轴见下” |
| 来源 | 网站、机构、文件名或平台 |
| **URL** | **原始链接（报告「参考资料」直接用它生成可点击引用）；拿不到就写“无”，不得编造** |
| 时间 | 发布日期或访问日期 |
| 适用范围 | 城市、片区、楼盘、户型、年份 |
| 置信度 | 高/中/低 |
| 备注 | 样本量、口径差异、是否挂牌价 |

## 数据源优先级

1. 政府与官方：统计局、教育局、住建局、规划资源局、民政/街道公开信息、学校官网或公众号。
2. 城市本地高频源 + 全国房产平台交叉验证：`杭房数研`、`小鸡选房`（杭州为主），贝壳/链家、我爱我家（全国通用）。
3. 交易与市场：安居客、房天下、诸葛找房、克而瑞、中指研究院、本地网签平台。
4. 地理与配套：高德/百度地图、地铁官网、医院/商圈/公园官方信息。
5. 舆情与口碑：主流媒体、自媒体、论坛、问答、业主讨论。只能做辅助线索。

## 全国城市数据源

| 数据源 | 覆盖 | 提供什么 | 可信度 | 取数机制 |
|---|---|---|---|---|
| **杭房数研** | 杭州（高频核心） | 每日新房/二手房签约、各小区成交价、一年量价走势；挂牌+成交双口径 | 中-高（接近网签口径，但部分做低） | 抓包 API（推荐）或联网检索兜底 |
| **小鸡选房** | 杭州（挂盘主力） | 板块/小区维度挂盘量、挂牌单价、带看、近期成交、小区画像 | 中（挂盘价反映卖方预期） | 抓包 API（推荐）或联网检索兜底 |
| **贝壳/链家** | 全国城市 | 挂牌、成交、小区详情、历史成交样本 | 中-高（成交记录为主） | 公开接口/页面 + 浏览器化请求；未配置则联网检索 |
| **我爱我家** | 全国城市 | 挂牌、成交、门店与小区信息 | 中 | 公开接口/页面 + 浏览器化请求；未配置则联网检索 |
| 安居客/房天下 | 全国城市 | 挂牌、小区基础信息 | 中（挂牌口径） | 联网检索为主 |

取数后必须在证据台账标注来源、URL、获取时间、口径（挂牌/成交）、样本量；把低可信口碑和高可信官方/平台数据分开使用。报告中的可点击引用（`render_citations`）直接取自台账 URL。

## 城市源注册表（预置内置）

`scripts/city_sources.json` 已预置**全国省会 + 自治区首府 + 直辖市（约 31 城）**的推荐信息源：每城含政府公开源（住建/网签/二手房公示）、省级政务 APP（浙里办类）、本地高价值小程序，外加全国网页源（贝壳/我爱我家，脚本已内置）。

- 取数前先跑 `python scripts/data_sources.py sources --city <城市>`，直接拿到该城推荐源与精确检索式，避免运行时再检索。
- 政府公开源多为无需登录的公示数据；深层明细（单套网签/合同）通常需实名或抓包，按下方反爬通道处理。
- 政务 APP（浙里办/随申办/粤省事/苏服办/皖事通等）含不动产/住房板块，属封闭生态，仅作检索提示 + 用户授权后抓包，不擅自突破登录墙。
- 注册表只存平台名 + 官方入口关键词 + 取数方式提示（`public_access` 标注无需登录公开页 / 需抓包 / 需登录），不硬编码易失效的深层 API。

## 价格时间轴（强制）

同一小区价格是波动的，**禁止只给一个“当前均价”就下趋势判断**。每个核心价格口径（挂牌、成交）至少给近 12-36 个月月度数据：

- 记录 `YYYY-MM`、当月均价、样本量（套）、口径（挂牌/成交）、来源。
- 报告必须列出峰值、谷值、当前值、月均波动幅度，以及 3/6/12/24/36 个月涨跌幅。
- 数据不足 5 个样本的月份写“样本不足”，不编造精确均价。

脚本统一用 `history` 字段承载时间轴，示例：

```json
{
  "community": "文鼎苑",
  "city": "上海",
  "source": "贝壳",
  "history": [
    {"community": "文鼎苑", "city": "上海", "date": "2026-06",
     "price_per_sqm": 61000, "kind": "listing", "count": 12, "source": "贝壳"},
    {"community": "文鼎苑", "city": "上海", "date": "2026-05",
     "price_per_sqm": 59500, "kind": "listing", "count": 9, "source": "贝壳"}
  ]
}
```

命令：

```bash
# 单源拉取，带上城市和时间轴长度
python scripts/data_sources.py fetch --source 贝壳 --community 文鼎苑 --district 浦东 --city 上海 --months 24

# 全源时间轴
python scripts/data_sources.py timeline --community 文鼎苑 --district 浦东 --city 上海 --months 24

# 学区流程 / 直接给小区流程也支持 --city
python scripts/data_sources.py school --school "某某小学" --city 上海 --budget 600 --area 90
```

## 反爬取数通道

贝壳、我爱我家等网站有 UA 校验、Cookie/登录态、JS 渲染、接口签名等常见反爬。本 skill 提供三条通道，不破解验证码、不做高频批量抓取、只采集公开页面数据：

1. **API 通道（优先）**：从浏览器 DevTools 或抓包拿到公开接口的 `endpoint` 与 `token`/`cookie`，写入 `scripts/sources.json`（参考 `scripts/sources.example.json`）。脚本会用浏览器化请求头直连。
2. **浏览器渲染通道（兜底）**：给对应源配置 `browser: true`、`cookie`、`headers`、`request_interval`，脚本先做浏览器化请求，拿不到时尝试本机已安装的 Playwright 渲染公开页面再解析。安装命令：`pip install playwright && playwright install chromium`（可选）。
3. **联网检索通道（默认兜底）**：未配置时，脚本生成“精确到数据源与城市”的检索式，由 AI 代理用 WebSearch / WebFetch 取数后回填 `listings` / `transactions` / `history`。

配置要点：

- `request_interval`：建议网页源 ≥ 1 秒，避免高频触发风控。
- `cookie` 与 `headers`：从浏览器开发者工具复制当前公开会话即可，不要把密钥写入仓库。
- `cities`：同一数据源可给不同城市配置不同 `endpoint`，脚本按用户声明城市自动选择。
- 反爬拦截或字段变化时，回退检索模式，并把失败原因和访问时间记入证据台账。

> 合规边界：只处理公开页面数据；不绕过登录墙获取非公开数据、不破解验证码、不伪造身份规避平台封禁、不短时间高频抓取。数据用途和频率需符合平台服务条款与当地法规。

## 可比样本

可比楼盘至少满足 2 个条件：

- 同城市同板块，或通勤/学校诉求相近。
- 总价带相近。
- 建成年代、产品类型、居住品质接近。
- 同一学校梯队或教育预期相近。

不要拿“纯学区老破小”和“品质改善次新房”直接比单价；必须拆成教育溢价、居住价值、流动性三个维度解释。

## 学区溢价样本

涉及学区房时，还必须按 `school-premium-comparison.md` 选择 2-3 个周边非学区或弱学区可比盘，用于估算目标房源相对普通居住价值的教育溢价。不要只做同学区内部小区比较。

## 数据处理规则

- 成交价优先于挂牌价；挂牌价只能反映卖方预期。
- 样本少于 5 套时，不要给精确均价，只给区间和样本说明。
- 同一小区必须按面积段、楼层、装修和户型拆分；学区房常见小户型单价高于大户型。
- 近 3 个月数据适合判断热度，近 12-36 个月适合判断趋势；趋势必须用月度时间轴，不能用两个孤立时点硬算。
- 遇到平台数据冲突时，列出口径差异，不强行合并成一个数字。

## 输出前检查

- 是否标注了所有核心价格的来源和时间？
- 是否区分了成交、挂牌、网签、评估和传闻？
- 是否给出月度时间轴、峰值/谷值/当前值、波动幅度和样本量？
- 是否说明样本量和户型面积段？
- 是否有 2-3 个真正可比对象？
- 如果是学区房，是否有周边非学区/弱学区可比盘和溢价率解释？
- 是否把低可信口碑和高可信官方数据分开使用？
