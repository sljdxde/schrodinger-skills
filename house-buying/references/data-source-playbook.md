# Data Source Playbook

本文件用于执行购房分析的数据采集。城市由用户声明，覆盖全国房源；采集时**先查证据，再下判断**：优先找一手原始来源，多源交叉验证，冲突时按优先级规则裁决，最后用证据台账承载不确定性。

技能内置五级数据源体系（T0-T4），配套 `scripts/city_sources.json`（约 46 城注册表）与 `scripts/data_sources.py`（取数编排）。**每一项被报告引用的数据都必须携带：来源 + 真实 URL + 发布时间/访问时间 + 数据口径 + 一致性程度**（见「引用格式规范」），杜绝凭空编造。

---

## 一、五级数据源体系（数据源清单）

| 层级 | 定位 | 数据源（2026-08 核验） | 提供什么 | 可信度 | 取数机制 |
|---|---|---|---|---|---|
| **T0 核心平台**（强制双源） | 挂牌/成交/带看/房源量的主证据 | **贝壳系**（贝壳找房 ke.com + 链家 lianjia.com）、**我爱我家**（5i5j.com） | 挂牌价、成交价、成交记录、在售房源量、带看量（贝壳小区页）、小区档案（物业/车位/容积率）、议价空间、成交周期 | 中-高（成交记录为主，挂牌反映卖方预期） | 公开接口/页面 + 浏览器化请求；未配置则联网检索 |
| **T1 官方佐证** | 最接近一手，冲突裁决最高权重 | 住建局/住建委官网、**网上房地产/网签备案平台**、**自然资源局/不动产登记中心**官网、统计局统计公报、教育局招生公告、公积金中心 | 网签/备案/成交公示、可售/挂牌套数、官方参考价、土地出让公告、人口与公报数据 | 高（口径最权威） | 多为无需登录公开页，直接抓；单套合同明细需实名/合同号 |
| **T1.5 城市本地高频源** | 接近网签口径的高频补充 | 杭房数研（杭州，日/月度网签+小区量价）、各城市本地权威小程序 | 每日签约、小区成交价、一年量价走势 | 中-高（接近网签，部分做低） | 抓包 API（推荐）或联网检索 |
| **T2 政务 App/小程序** | 政策与交易数据补充、封闭生态 | 浙里办（e房通/房屋租售）、随申办、**京通**（北京通）、粤省事、苏服办、爱山东、闽政通、辽事通等省级 App；城市官方小程序（莞e住建、泉房通、郑好房、邕有家等） | 政策原文、不动产/购房资格核验、个人名下房产、公积金、网签办理 | 高（官方，但封闭生态） | 仅作检索提示 + 用户授权后抓包，不擅自突破登录墙 |
| **T3 交叉验证** | 只做交叉比对，不单独支撑结论 | **诸葛找房**（聚合）、**安居客**、**房天下**、**58同城房产**（重复房源多、可信度最低）、幸福里、克而瑞、中指研究院 | 挂牌价、小区均价、聚合走势（多平台数据） | 中（挂牌口径；58同城低） | 联网检索为主；诸葛/安居客/房天下/58同城已内置脚本适配器 |
| **T4 舆情口碑** | 线索级，不能单独支撑结论 | 主流媒体、自媒体、论坛、问答、业主群 | 口碑、情绪、传闻 | 低 | 检索，引用时注明"非官方" |

**取数总原则**：

- **关键数据（成交价/挂牌价/小区档案）至少双源**：T0 双平台（贝壳系 + 我爱我家）交叉核对；官方有公示时用 T1 佐证；杭州叠加 T1.5 高频源。
- **同一指标尽量多源交叉比对**，并在引用中标注一致性程度（双源一致 / 单源 / 来源冲突）。
- 单源可得时标注「（单源：XX）」并降置信度。

## 二、证据台账（7+2 列）

每条关键结论用下表自查，**必须逐项填写，不允许空来源**：

| 字段 | 写法 |
|---|---|
| 事实/数据 | 例如"近一年主力成交单价约 X 万/㎡，月度时间轴见下" |
| 来源 | 网站、机构、文件名或平台（含 T 层级，如 T0 贝壳 / T1 住建局） |
| **URL** | **原始链接（报告「参考资料」直接用它生成可点击引用）；拿不到就写"无"，不得编造** |
| **时间** | 发布/更新日期 + 访问日期（引用格式规范要求，缺一不完整） |
| **口径** | 成交 / 挂牌 / 网签 / 参考均价 / 评估价 / 网传价，必须写明 |
| 适用范围 | 城市、片区、楼盘、户型、年份 |
| 置信度 | 高 / 中 / 低 |
| **一致性** | 该数据点被几个独立来源确认：双源一致 / 单源 / 来源冲突 |
| 备注 | 样本量、口径差异、是否含大户型等 |

## 三、引用格式规范（防伪机制，强制）

技能中引用的**每一项数据**必须携带五要素，报告正文与文末参考资料同时体现：

```
[来源] 标题 —— 发布时间/访问时间；口径：成交/挂牌/网签；一致性：双源一致
—— 真实 URL（可点击）
```

1. **正文**：关键数字后标引用锚点 `<a href="#cite-N" class="cite-ref">[N]</a>`，点击跳转到文末对应条目。
2. **文末参考资料**：用 `scripts/data_sources.py` 的 `render_citations(cites)` 生成，每条 `<li>` 支持四个字段：

```python
cites = [
    {
        "label": "贝壳·杭州·坤和西溪里小区页",          # 来源 + 标题（必填）
        "url": "https://hz.ke.com/xiaoqu/xxxx/",      # 真实 URL（必填）
        "date": "2026-07-15 访问",                     # 发布时间或访问时间
        "caliber": "挂牌",                             # 数据口径
        "consistency": "双源一致",                     # 一致性程度
    },
    ...
]
```

   渲染结果示例：
   `<li id="cite-1"><a href="...">贝壳·坤和西溪里小区页</a> <span class="cite-meta">[2026-07-15 访问；口径:挂牌；一致性:双源一致]</span></li>`

3. **红线（违反即返工）**：
   - 只能引用真实抓取/检索到的 URL；没拿到 URL 的写"未提供链接"，**不得编造 URL**。
   - 政府文件、官网、平台详情页优先于转载/自媒体；低可信来源在引用文本里注明"非官方"。
   - 同一数据点的发布时间、口径缺失时，标"时间未知/口径未知"，不得默认。

## 四、冲突处理逻辑（多源冲突裁决）

多源数据冲突时按以下优先级裁决，**不强行合并成一个数字**：

**优先级规则（从高到低）**：

1. **时间最新**：更新/发布时间更新的数据优先（注明数据截止日期）。
2. **口径最权威**：官方（T1）> 核心平台成交记录（T0）> 城市高频源（T1.5）> 政务 App（T2）> 挂牌口径平台（T3）> 舆情（T4）。
3. **最接近一手**：官方网签/备案/不动产登记（一手）> 平台成交记录 > 平台挂牌 > 聚合/转载。

**处置要求**：

- 数值差异 ≤5% 视为一致，可给区间或取权威口径，标注"双源一致"。
- 差异 >5%：**并列披露双方数字与口径差异**（如挂牌 vs 成交、含大户型 vs 纯小户），结论写成区间，不取一方直接写死。
- 无法解释的硬冲突（如链家写"人车分流"、幸福里写"无"）：结论标**「存疑/来源冲突」**，报告中列出不同来源说法。
- 单一来源的数据必须标注「单源」，置信度降为中-低。

## 五、第一维度：房价（每次必做，数据链路起点）

单一维度展开策略的第一步（完整框架见 `references/dimension-network.md`）：先把「房价」维度做透，建立月度数据链路，再按用户诉求逐层扩展到成交量、供需比、土地出让、学区/政策、人口流动、信贷环境。

**房价维度字段清单**：

| 字段 | 定义 | 强制要求 |
|---|---|---|
| 挂牌价 | 在售房源挂牌均价（月度） | 月度时间轴，至少 12-36 个月 |
| 成交价 | 已成交房源均价（月度） | 月度时间轴；成交价优先于挂牌价 |
| 环比 MoM | 本月 / 上月 - 1 | 由 `compute_mom_yoy()` 计算，缺月不编造 |
| 同比 YoY | 本月 / 去年同月 - 1 | 由 `compute_mom_yoy()` 计算 |
| N 月涨跌幅 | 3/6/12/24/36 个月 | 当前月 vs 恰好 N 个月前（日历月差） |
| 带看量 | 小区近 30 天带看次数（贝壳小区页） | 有则采，无则标"未披露" |
| 在售房源量 | 当前挂牌在售套数 | 挂牌量是供需比的前置数据 |
| 议价空间 | 挂牌价 vs 成交价价差 | 有样本则计算 |
| 成交周期 | 挂牌到成交平均天数 | 有样本则计算 |

**输出**：报告「交易与价格」章节必须含——

1. 挂牌 vs 成交双序列走势图（`render_timeline_chart`，内嵌 SVG）；
2. 月度时间轴表格（月份/挂牌均价/样本量/成交均价/样本量/来源）；
3. 峰/谷/当前值 + 环比/同比 + 3/6/12/24/36 月涨跌幅（`compute_mom_yoy()` 输出）；
4. 样本不足 5 套的月份写"样本不足"，不编造精确均价。

命令：

```bash
python scripts/data_sources.py timeline --community 坤和西溪里 --city 杭州 --months 36   # 全源时间轴 + SVG
python scripts/data_sources.py fetch --source 贝壳 --community 坤和西溪里 --city 杭州 --months 24
python scripts/data_sources.py dimensions --dimension price   # 查看房价维度字段与来源
```

## 七、小区名称、学区与核心事实核验（强制）

出报告前必须先完成以下核验；任何一项无法确认时，在「存疑/不确定性」章节明确写出，不得把低可信来源当事实写进结论。

### 1. 小区名消歧

- 每一个目标小区名必须通过**贝壳系（贝壳/链家）、我爱我家、透明售房网/好找房或政府房产登记平台**验证其真实存在性；平台返回的「小区页」是小区存在的强证据。
- **禁止脑补近似名**：如发现「西溪里璞园」「坤和西溪里北区」等名称与平台真实条目不一致，必须：
  1. 列出平台真实条目名（如链家：坤和西溪里 / 坤和西溪里璞园）；
  2. 说明用户/第三方 App 的命名口径；
  3. 报告正文以用户认可的本地口径为主标题，但必须在「数据来源与口径说明」中披露差异。
- 遇到同名或近似名跨行政区（如「佳兆业西溪璞园」vs「坤和西溪里璞园」），必须加**醒目警示框**，避免看房时跑错盘。

### 2. 学区对口核验

- **学校名称必须先看教育局当年招生公告**：每个城市/区每年会发布《义务教育阶段学校招生工作方案》，里面明确「教育服务区范围」或「对口小区清单」。这是学区判断的最高权威。
- 若教育局以「四至边界」描述学区，则把目标小区在地图上核对是否落入边界；同时用链家/小鸡选房等学区房清单做交叉验证，但**不能反过来用第三方清单替代教育局边界**。
- 集团化学校要特别注意校区/分校差异：如「文澜实验学校（桥西）」「文澜实验小学（上塘）」「文澜实验中学（文澜校区/慧澜校区）」是不同的学校/校区，必须区分，不得混用。
- 学区对口必须同时确认**对口小学**和**对口初中**；初中若为新设/校区，需查到教育局或学校官方的对口直升文件。

### 3. 人车分流、物业、建成年代等社区事实

- 人车分流、物业归属、建成年代、车位比、容积率优先采信**贝壳系（贝壳/链家）小区页、我爱我家小区页、透明售房网、政府公示**；安居客/房天下/幸福里仅作交叉验证。
- **每项基础信息必须带来源**：物业公司、建成年代、车位比、容积率、人车分流等每一项，都要在证据台账记录「平台 + 小区页 URL + 获取日期」；报告正文的对应单元格必须加**引用锚点**（如 `[3]`），参考资料列表给出该小区页真实 URL。禁止出现「无来源的基础信息」。
- **物业公司名称以小区页/官方口径为准，房源页/经纪人解读仅作交叉验证**：同一小区多来源写法可能不同（如「万科物业发展有限公司」vs「上海万科物业服务有限公司杭州分公司」），取小区页/多源一致口径，必要时并列披露两个来源。
- 若多个平台冲突（如链家房源写「人车分流」、幸福里写「无」），结论写成**「存疑」或「来源冲突」**，并在报告中列出不同来源的说法，不得取其中一方直接写死。
- 地铁距离以**高德/百度地图步行距离**或平台小区页数据为准，标注测量起点（如「五常站C口→小区东门约 X 米」）。

### 4. 价格数据

- 成交价优先于挂牌价；同一小区的「参考成交均价」「挂牌均价」「小区评估价」口径不同，必须分开写，不能混用。
- 给预算匹配建议时，使用**当前真实在售/成交样本**（面积+总价+单价），而不是单一的「小区均价」；小区均价会受大户型/别墅/车位等拉高，可能严重误导预算判断。
- 所有价格样本必须标注来源 URL、获取日期、是挂牌还是成交。

## 八、全国城市数据源（46 城注册表）

`scripts/city_sources.json` 已预置**全国省会 + 自治区首府 + 直辖市 + 计划单列市 + 强地级市（约 46 城）**的推荐信息源。新增城市（深圳/宁波/青岛/厦门/大连/苏州/无锡/东莞/佛山/温州/泉州/南通/嘉兴/珠海/洛阳等）gov URL 均经 2026-08 联网核验。

- 取数前先跑 `python scripts/data_sources.py sources --city <城市>`，直接拿到该城推荐源与精确检索式，避免运行时再检索。
- 政府公开源多为无需登录的公示数据；深层明细（单套网签/合同）通常需实名或抓包，按「反爬取数通道」处理。
- 政务 App（浙里办/随申办/京通/粤省事/苏服办/皖事通等）含不动产/住房板块，属封闭生态，仅作检索提示 + 用户授权后抓包，不擅自突破登录墙。
- 注册表只存平台名 + 官方入口关键词 + 取数方式提示（`public_access` 标注无需登录公开页 / 需抓包 / 需登录），不硬编码易失效的深层 API。
- 未内置城市回退到：T0 双源 + T3 交叉源 + 联网检索。

### 城市源分级要点（举例，2026-08 核验）

| 城市 | 高价值公开源 | 取数要点 |
|---|---|---|

## 九、价格时间轴（强制）

同一小区价格是波动的，**禁止只给一个"当前均价"就下趋势判断**。每个核心价格口径（挂牌、成交）至少给近 12-36 个月月度数据：

- 记录 `YYYY-MM`、当月均价、样本量（套）、口径（挂牌/成交）、来源。
- 报告必须列出峰值、谷值、当前值、月均波动幅度，以及 3/6/12/24/36 个月涨跌幅（`compute_mom_yoy()` 直接输出）。
- 数据不足 5 个样本的月份写"样本不足"，不编造精确均价。

脚本统一用 `history` 字段承载时间轴，示例：

```json
{
  "community": "文鼎苑",
  "city": "上海",
  "source": "贝壳",
  "history": [
    {"community": "文鼎苑", "city": "上海", "date": "2026-06",
     "price_per_sqm": 61000, "kind": "listing", "count": 12, "source": "贝壳"},
    {"community": "文鼎苑", "city": "上海", "date": "2026-05",
     "price_per_sqm": 59500, "kind": "listing", "count": 9, "source": "贝壳"}
  ]
}
```

命令：

```bash
# 单源拉取，带上城市和时间轴长度
python scripts/data_sources.py fetch --source 贝壳 --community 文鼎苑 --district 浦东 --city 上海 --months 24

# 全源时间轴（含 SVG 走势图）
python scripts/data_sources.py timeline --community 文鼎苑 --district 浦东 --city 上海 --months 24

# 学区流程 / 直接给小区流程也支持 --city
python scripts/data_sources.py school --school "某某小学" --city 上海 --budget 600 --area 90
```

## 十、反爬取数通道

贝壳、我爱我家等网站有 UA 校验、Cookie/登录态、JS 渲染、接口签名等常见反爬。本 skill 提供四条通道，不破解验证码、不做高频批量抓取、只采集公开页面数据：

1. **贝壳官方 CLI 通道（个人合规，T0 首选）**：调用贝壳官方 `beike` CLI（LianjiaTech/beike-ai-platform），返回结构化 JSON，不抓页面、不破验签，是接入「真实平台数据」最稳的合规通道。详见「贝壳官方 CLI」专章。
2. **API 通道（优先）**：从浏览器 DevTools 或抓包拿到公开接口的 `endpoint` 与 `token`/`cookie`，写入 `scripts/sources.json`（参考 `scripts/sources.example.json`）。脚本会用浏览器化请求头直连。
3. **浏览器渲染通道（兜底）**：给对应源配置 `browser: true`、`cookie`、`headers`、`request_interval`，脚本先做浏览器化请求，拿不到时尝试本机已安装的 Playwright 渲染公开页面再解析。安装命令：`pip install playwright && playwright install chromium`（可选）。
4. **联网检索通道（默认兜底）**：未配置 / 官方 CLI 不可用 / 调用失败时，脚本生成"精确到数据源与城市"的检索式，由 AI 代理用 WebSearch / WebFetch 取数后回填 `listings` / `transactions` / `history`。

### 合规红线（法律风险，必读）

取数通道的**首选是官方开放 API，而非个人抓包**。近年司法实践已明确边界：

- **首选：贝壳开放平台官方 API**（企业实名认证 OAuth2.0）。单 IP 日调用上限约 10 万次、并发约 50/s，返回脱敏数据，是合规且稳定的结构化通道。配置方式见 `scripts/sources.example.json` 的 `endpoint`/`token` 字段。
- **法律红线（个人用户务必避开）**：法院已认定贝壳房源库受法律保护，**未经授权批量爬取构成不正当竞争**；**破解接口验签算法涉刑，已有判例主犯获刑 3.5 年**。因此对核心接口做个人抓包、逆向验签、伪造请求，对自然人存在现实刑事风险。
- **默认回退「联网检索兜底」**：未配置官方 API 时，走脚本生成的精确检索式 + AI 代理公开检索，绝不鼓励个人破解验签或高频批量抓取。
- **政务 App（浙里办/随申办/京通等）含个人隐私查询**（学位占用、不动产），仅作检索提示与用户授权后的本人查询，**不擅自突破登录墙**。

> 合规边界：只处理公开页面数据；不绕过登录墙获取非公开数据、不破解验证码与验签算法、不伪造身份规避平台封禁、不短时间高频抓取。数据用途和频率需符合平台服务条款与《反不正当竞争法》等当地法规。

### 贝壳官方 CLI（个人合规通道，T0 首选）

贝壳官方提供 CLI 工具 `beike`（仓库 `LianjiaTech/beike-ai-platform`），经官方鉴权返回结构化数据，**不抓页面、不破验签**，是接入「真实平台数据」的首选合规通道。本 skill 的 `BeikeCliSource` 已对齐「贝壳买房专家」的命令体系做多命令聚合。

**安装与鉴权（一次性）**

```bash
# 1) 安装 CLI（官方安装脚本）
curl -fsSL https://raw.githubusercontent.com/LianjiaTech/beike-ai-platform/master/cli/releases/install.sh | bash
# 2) 获取 API Key（浏览器登录后生成）
#    https://building.ke.com/?action=get-key&source=house-buying
# 3) 保存 Key 到本机（默认写入 ~/.beike/BEIKE_MCP_API_KEY）
beike auth <YOUR_API_KEY> --save
```

**命令体系（对齐「贝壳买房专家」）**

| 命令 | 用途 | 进入报告的位置 |
| --- | --- | --- |
| `beike buy search -c <城市拼音> -q <小区>` | 当前挂牌 | `listings` + 详情 URL |
| `beike buy sold -c <城市拼音> -q <小区>` | 近期成交 | `transactions`（无单价自动反算；全维度存 `details`） |
| `beike buy market -c <城市拼音> -q <小区>` | 均价走势 | `history`（月度 PricePoint） |
| `beike buy resblock -c <城市拼音> -q <小区>` | 小区档案 | `extra.resblock`（含真实 xiaoqu URL） |

> 调用时脚本**强制追加 `--json`** 拿到结构化输出（默认是友好纯文本）。`-c` 传**城市名**（如 `杭州`，不是拼音；实测 `-c hz` 返回 0 结果）；`-q` 传自然语言查询（如「银树湾近一年成交」）。`CITY_PINYIN` 仅用于拼 ke.com 详情 URL，与 `-c` 无关。

**输出格式与解析要点（真实探测结论，v0.2.x）**

- `--json` 返回 `{"data": "<长文本>"}`；但 `buy search` 等多子查询命令会**一次性拼接返回多段 JSON**（房源段 + 新房段…），直接整体 `json.loads` 会报「Extra data」——解析时取「data 字段最长」的那一段（房源段信息最全）。
- 房源/小区块用 `<标识>\n{JSON}\n</标识>` 包裹，但**所有字段嵌套在 `基本信息` 或 `摘要信息` 下**，且不同命令结构不同，解析必须按命令区分：
  - **`sold` 成交**：`{"基本信息":{成交价格(万)/成交日期(点分隔 2026.04.26)/房源名称(含「N室N厅 X㎡」)/小区ID/挂牌价格/朝向/楼层…}}`。**无单价** → 由 `成交价格×10000 / 面积` 反算；房源 ID = **区块标签**（`<103149593520>`），不在 JSON 内。
  - **`search` / `resblock`**：`{"摘要信息":{价格信息(总价+单价)/房源标题/房源ID/小区信息(含小区ID的中文串)/户型信息/房源售卖状态/学区信息/小区名称/市场行情}}`。
- 价格是中国字符串：`总价899万，单价52595元/平米` 或 `成交价格315万`；成交单价需反算。房源 ID 拼出**真实 ke.com 详情 URL**：`https://{城市拼音}.ke.com/ershoufang/{房源ID}.html`（成交为 `/chengjiao/`）；小区档案拼 `https://{城市拼音}.ke.com/xiaoqu/{小区ID}.html`。报告引用必须指向真实 URL，严禁伪造。
- **`market` 均价走势**：`<价格走势><小区名行情>\n{小区最新行情}\n{小区行情数据:{成交均价/挂牌均价/成交量:{最近6月趋势:{"2026-02":"3.37万/m2",...}}}}\n</小区名行情>`（区块内含**多段 JSON**）。均价用「万/m2」写法（需 ×10000→元/㎡），成交量用「N套」；按 `(date, kind)` 去重，成交均价/挂牌均价/成交量三类各自保留。
- **日期格式为点分隔**（`2026.04.26`），解析时归一为 `YYYY-MM-DD`；`search` 挂牌无成交日期，取 `房源动态` 里最近一次调价日。
- **`sold` 成交维度全量捕获**：除价格/面积/日期外，`_beike_block_to_row` 一并抽取 关注人数/总带看次数/成交周期/朝向/权属/楼型/楼层/用途/电梯/装修/年代，连同价格信息、交易信息、单元楼栋信息、房源亮点、房源动态、同户型行情等，全部存入每行 `details` 字典，供 `render_transaction_details` 生成「房屋成交详细信息」逐条卡片（缺字段不展示、绝不编造）。
- **学区**在 `search` 块的 `摘要信息.学区信息`（如「对口杭州市文澜实验学校」），是 house-buying 核心关注点，需带入报告。
- `resblock` 官方 CLI **不直给「均价」**——均价改由 `market`/`sold` 聚合；`摘要信息.市场行情` 含「在售 N 套、价格范围 X-Y 万」，可抽在售套数与价格区间。

**多命令聚合与兜底（防伪纪律）**

- 四条命令**独立调用、独立兜底**：任一命令失败只少一类数据，不整体异常（失败原因记入证据台账 `raw_note`）。
- 全部命令失败 / 无可用数据 → 自动退回联网检索模式（`mode="cli_unavailable"`，给出精确检索式），**绝不编造或假装成 CLI 真实数据**。
- 解析不出字段 → 该字段留空并在 `raw_note` 标注「已退回检索」，不补默认值。
- 详情页、VR、图片链接一律用上游真实 ID 生成；`isError=true` 视为服务不可用，明确告知用户而非编造。

配置要点：

- `request_interval`：建议网页源 ≥ 1 秒，避免高频触发风控。
- `cookie` 与 `headers`：从浏览器开发者工具复制当前公开会话即可，不要把密钥写入仓库。
- `cities`：同一数据源可给不同城市配置不同 `endpoint`，脚本按用户声明城市自动选择。
- 反爬拦截或字段变化时，回退检索模式，并把失败原因和访问时间记入证据台账。

> 合规边界：只处理公开页面数据；不绕过登录墙获取非公开数据、不破解验证码、不伪造身份规避平台封禁、不短时间高频抓取。数据用途和频率需符合平台服务条款与当地法规。

## 十二、可比样本

可比楼盘至少满足 2 个条件：

- 同城市同板块，或通勤/学校诉求相近。
- 总价带相近。
- 建成年代、产品类型、居住品质接近。
- 同一学校梯队或教育预期相近。

不要拿"纯学区老破小"和"品质改善次新房"直接比单价；必须拆成教育溢价、居住价值、流动性三个维度解释。

## 十三、学区溢价样本

涉及学区房时，还必须按 `school-premium-comparison.md` 选择 2-3 个周边非学区或弱学区可比盘，用于估算目标房源相对普通居住价值的教育溢价。不要只做同学区内部小区比较。

## 十四、数据处理规则

- 成交价优先于挂牌价；挂牌价只能反映卖方预期。
- 样本少于 5 套时，不要给精确均价，只给区间和样本说明。
- 同一小区必须按面积段、楼层、装修和户型拆分；学区房常见小户型单价高于大户型。
- 近 3 个月数据适合判断热度，近 12-36 个月适合判断趋势；趋势必须用月度时间轴，不能用两个孤立时点硬算。
- 遇到平台数据冲突时，按「四、冲突处理逻辑」裁决：列出口径差异，不强行合并成一个数字。

## 十五、输出前检查

- 是否标注了所有核心价格的来源、时间和口径（成交/挂牌/网签）？
- 引用是否满足五要素：来源 + URL + 时间 + 口径 + 一致性？
- 是否给出月度时间轴、峰值/谷值/当前值、波动幅度、样本量、环比/同比与 N 月涨跌幅？
- 关键数据是否至少双源交叉（T0 双平台 / T1 佐证）并标注一致性？
- 是否有 2-3 个真正可比对象？
- 如果是学区房，是否有周边非学区/弱学区可比盘和溢价率解释？
- 是否把低可信口碑和高可信官方/平台数据分开使用？
