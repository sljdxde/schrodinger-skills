# Intake Questionnaire

本文件定义 `house-buying` 的交互式启动规则。默认先问清楚用户需求，再采集数据和生成报告。购房结论高度依赖家庭约束，信息不完整时必须先追问。

## 核心约定

- **全国房源**：城市由用户声明即可，不限定杭州。脚本按声明城市自动从 `scripts/city_sources.json` 选源（全国网页源 + 该城政府公开源 + 政务 APP + 本地小程序）。
- **首付比例必填**：用户**自行填写实际首付百分比**（如 30%），用于计算所需现金、月供与购买可行性。**不再追问"首套/二套"**——若需判断限购/限贷资格，在报告里基于声明城市 + 首付比例提示，而非在 intake 追问。
- **价格时间轴**：报告强制给出月度走势图（见 `report-template.md`）。intake 可顺带问"希望看近多少个月"，默认 36 个月。

## 字段分级

### 必填字段

| 字段 | 说明 | 缺失时处理 |
|---|---|---|
| 城市 | 目标城市（全国任意城市，声明即可） | 必须追问 |
| 目标对象 | 小区、楼盘、学校或片区 | 必须追问 |
| 购房目的 | 自住、学区、改善、投资或组合 | 必须追问 |
| 预算 | 总价或单价预算 | 必须追问 |
| 首付比例 | **用户填写的实际首付百分比（如 30%）** | 必须追问 |
| 入学年份 | 孩子预计上小学/初中的年份；不涉及学区可填"无" | 学区相关必须追问 |

### 可选字段

| 字段 | 说明 | 缺失时处理 |
|---|---|---|
| 户型/面积 | 几房、面积段、楼层、房龄偏好 | 可默认"未指定" |
| 月供上限 / 贷款额度 | 家庭可承受月供、可贷额度 | 可默认"未指定" |
| 时间窗口 | 希望看近 12 / 24 / 36 个月走势，默认 36 | 可默认 36 |
| 通勤与配套 | 上班地点、老人照护、地铁/医院/商圈偏好 | 可默认"未指定" |
| 决策时间 | 马上、3 个月、半年、1 年以上 | 可默认"观望" |
| 备选项 | 备选小区、学校、片区或明确排除项 | 可默认"无明确备选" |

## 首轮提问模板

用户信息不足时，使用下面的问题一次性收集，最多 8 个：

```text
为了避免信息缺失导致误判，我先确认几个关键约束：

1. 目标城市是哪里？（全国房源，直接说城市名即可，例如上海 / 北京 / 杭州）
2. 你想分析的小区、楼盘、学校或片区是什么？
3. 购房目的是什么：自住、学区、改善、投资，还是组合？
4. 总预算或单价预算是多少？
5. 首付比例大概多少？（填实际百分比，比如 30%，用于算月供和可行性）
6. 孩子预计哪一年上小学/初中？如果只是自住可填“无”。
7. 想看近多少个月的价格走势？默认 36 个月（可选 12 / 24）。
8. 户型面积偏好、月供上限（可选）是什么？
```

## 追问策略

- 只给城市和楼盘，例如“分析上海耀江文鼎苑”：追问预算、购房目的、首付比例、入学年份和决策时间。
- 只给城市和泛需求，例如“想买成都学区房”：先要求缩小到目标学校、片区或 2-3 个候选小区。
- 已给关键字段，例如“上海耀江文鼎苑，自住+学区，预算 400 万，首付 35%，孩子 2029 年上小学”：直接开始分析，缺失的户型、月供上限、时间窗口列为假设（时间窗口默认 36 个月）。
- 用户拒绝补充某项信息：继续分析，但在报告中标注“用户未提供”，并降低相关结论置信度。
- 用户目标明显冲突，例如“投资为主但不接受价格波动”：先指出冲突并要求确认优先级。

## 进入分析的门槛

满足以下条件才开始完整数据采集：

- 城市明确（任意全国城市均可声明）。
- 目标对象明确到小区、楼盘、学校、片区或候选列表。
- 购房目的明确。
- 预算明确，或用户明确表示“先不设预算”。
- **首付比例明确**（用户填写的实际百分比）。
- 学区相关需求必须明确入学年份；非学区需求可写“无”。

不满足门槛时，不输出完整报告，只输出追问清单。
