# milestone-playbook（里程碑编排手册）

本文件是 milestone-gate 的执行权威。它规定了「何时拆分、粒度怎么定、验收怎么写、不达标怎么回退」，以及和既有安全规则的协同方式。

## 1. 何时启用里程碑（触发判据）

满足任意一条 → 启用 milestone-gate：

- **多步骤**：预计 ≥ 5 个工具调用，或 3+ 个串行子任务。
- **高成本**：涉及大文件下载/处理、长耗时构建、付费 API、GPU/算力消耗。
- **多维交付**：最终产物含多个文件（HTML+报告+视频等）或多部分答案。
- **不可逆风险**：涉及个人目录的删除/移动/重命名、发布、对外发送、账号变更。
- **用户显式要求**：出现「分步」「先设计」「每日/每周」「定期」「先规划」等词。
- **用户抱怨**：出现「只看到结果」「看不到过程」「重来太费 token」等反馈。

**不启用**：单步或一眼能完成的任务——直接做，避免啰嗦。判断拿不准时，默认启用（宁可多一层，也别赌最后一把）。

## 2. 粒度建议

- 一个里程碑 = 一个「可交付、可验收」的阶段性产出，不是「读个文件」「跑条命令」这种碎步。
- 太大（≥ 10 步还无中间交付）→ 拆细；太小（一步就能验证）→ 合并。
- 危险/不可逆动作**单独成里程碑**，且放在「危险前置」子流程里（见第 4 节）。
- 给用户看里程碑清单时，标注当前阶段（in_progress）与已完成项。

## 3. 验收标准（Acceptance Criteria）写法模板

每个里程碑的「验收标准」必须是**可核验**的，避免「差不多」「看起来对」。推荐四件套：

| 维度 | 写什么 |
|---|---|
| 重要产出 | 具体文件路径 / 命令输出的关键行 / 关键结论 |
| 文件变更 | 哪些文件被创建或修改，改了什么 |
| 结论/风险 | 得出的关键结论、未解决的风险 |
| 下一步 | 明确下一步动作（或「无需」） |

示例：
> 「产出 `report.html`；包含 3 张图表与结论段；关键数字已核对来源；无未解决阻断。下一步：用户确认后做 PPT 版。」

## 4. 回退重做与保留已完成项

- **不达标 → 退回该里程碑重做**：已达标的前序里程碑**保留**，不推翻重来（这正是省 token 的核心）。
- **失败立即停**：任一里程碑执行失败，先报告失败点与已产出物，再等长/下次确认，不静默继续。
- **小批量**：修正/删除类动作单次 ≤ 10 文件，逐批验证。

## 5. 与「个人文件安全」规则协同

里程碑门控**不替代**个人文件安全规则，而是与之叠加：

- 涉及桌面/下载/文档等个人目录的扫描/删除/整理 → 先扫描只读生成报告，不动作。
- 破坏性动作前先警告：「⚠️ 此操作非常危险，可能导致不可逆的数据丢失！」并 listing 受影响路径。
- 即使里程碑门控要求「继续」，个人文件的删除仍必须走 Trash/备份，不经过 rm/del。

## 6. 与 Plan / Craft / Ask 模式的分工

- **Plan 模式**：本 skill 的「画里程碑」与 Plan 模式思路一致，但 milestone-gate 不需要用户先切模式——它在 Craft 模式下自动施加「画里程碑 + 阶段确认」的流程。
- **Ask 模式**：仅分析不执行时，本 skill 退化为「只规划里程碑与验收标准」，不动手。
- **Craft 模式**：默认落地执行，按里程碑逐段推进。
