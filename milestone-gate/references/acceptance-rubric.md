# acceptance-rubric（达标判据与分级处理）

本文件规定「怎么算达标」以及「不达标时怎么分级处理」。它是 milestone-gate 的验收标尺。

## 1. 清单式验收模板

每个里程碑结束时，用下面的清单做验收（逐项打勾，未勾完不算达标）：

- [ ] **重要产出**：命令输出/文件/数据是否符合预期（列出关键行或路径）
- [ ] **文件变更**：被创建/修改的具体文件与变更点已记录
- [ ] **结论/发现**：关键结论、错误、未解决风险已汇总
- [ ] **下一步**：明确了后续动作或显式标记「无需」

达标 = 四项全勾。任一项缺失 → 不达标，退回重做。

## 2. 不达标分级处理（P0 / P1 / P2）

| 级别 | 含义 | 处理 |
|---|---|---|
| **P0** | 数据丢失/不可逆/违反安全或法律 | 立即停；**强烈警告**并要求二次确认；绝不自动继续 |
| **P1** | 关键结果错误、阻塞后续、损失可恢复但成本高 | 警告并说明风险，要求显式确认后再继续 |
| **P2** | 局部瑕疵、排版/细节问题、可快速修复 | 直接修正，无需二次确认，修正后重新验收 |

规则：P0/P1 在 destructive 动作前必须先列受影响路径 + 风险，再要求确认；P2 不打断流程。

## 3. 二次确认机制

- 危险操作（删除/清空/重命名个人目录、广通配、rm -rf 等）即便用户坚持也须先警告并备份。
- 经 OS 回收站机制删除，不物理删除；无回收站时警告并要二次确认。
- 个人文件单次 ≤ 10 个，逐批验证，任一失败立即停。

## 4. 未达标时的回复要求

最终给用户的最终可见回复必须**独立成篇**地回答请求，把重要结果从折叠的中间步骤里带出来：重要输出、文件路径、结论、错误、未决风险、下一步。用户只读最终回复也能看懂结果。
