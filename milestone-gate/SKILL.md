# 里程碑门控

复杂任务的里程碑门控：开局画清里程碑与验收标准，每完成一段交付给你确认，不达标就回到上一段重做，直到达标再往下走——把「最后一把赌结果」变成「每段都可纠偏」。

## 核心原则

- 开局先拆里程碑，让用户看到全貌与验收标准，再动手。
- 每个里程碑必须有「可核验的交付物 + 达标判据」，模糊的「差不多」不算达标。
- 不达标就退回该里程碑重做，已达标的前序里程碑保留，绝不推翻重来。
- 只在里程碑结束请求确认，不每一步都打断；简单任务不强加里程碑。

## 何时触发

当用户给出需要多步完成的复杂任务（建站/写代码/研究写作/数据分析/批量操作/可视化等），或隐式要求「分步、先设计、定期做」时使用本 skill；也适用于用户抱怨「只看到结果、看不到过程」的场景。


**适用对象：** 任何需要在电脑上完成复杂任务的人；默认中文用户。用户希望掌控过程、避免不可逆返工，但不想每步都手动切到 Plan 模式。

## 输入与数据来源

- **输入渠道**：用户自然语言指令；可附带文件/URL/截图作为上下文
- **输入格式**：text；file；url；image
- **必填项**：用户目标（隐含在 query 中）
- **选填项**：验收偏好；目标目录/文件路径；时间预期
- **缺失关键项时**：目标模糊时先澄清目标与验收标准，不假设；模糊的「清理/整理」类请求先问清目标再行动。


## 工作流

### 1. 任务画像

判断任务是否值得里程碑化：多步骤 / 高成本 / 多维交付 / 不可逆风险 / 用户显式分步要求 → 启用；简单一眼能完成的任务直接做，不强行拆分。

### 2. 画里程碑

把目标拆成有序里程碑，每个明确「交付物 + 验收标准」，开局用任务清单展示给用户，并标明当前所处阶段。

### 3. 逐里程碑执行

执行当前里程碑 → 产出交付物 → 通过预览/卡片/摘要呈现 → 请求用户确认是否达标。

### 4. 门控判定

达标→标记完成并进入下一步；不达标→退回该里程碑重做（保留已达标前序），直到达标；任一环节失败立即停并报告。

### 5. 收尾交付

全部里程碑达标后，用 present_files 给出最终可查看交付物，并附简明结论（关键结果、风险、下一步）。

## 输出规格

- **交付形态**：每里程碑的中间交付物（artifact 卡片/内置预览）+ 最终交付物 present_files
- **结构组成**：里程碑清单与验收标准；各阶段中间交付物；最终交付物与结论
- **篇幅与详略**：按需；每个里程碑给最高信号摘要，不堆砌
- **语气与语言**：简洁直接，结论先行
- **交付物/文件名约定**：最终交付文件（HTML/报告/pptx/video/代码等）；每阶段中间产物（如需）


## 交互方式

- **交互模式**：开局先画里程碑计划，每里程碑结束请求确认；不达标可回退重做，无需切到 Plan 模式。
- **澄清风格**：目标或验收标准不清时先问，不猜测；能推断的列为假设请确认。
- **不确定时的处理**：模糊请求先拆目标目录/标准再行动；扫描只读、危险操作先警告再确认。


## Skill 边界

**包含：**

- 多步骤任务的里程碑拆分与验收标准制定
- 中期交付物的呈现与用户确认
- 不达标时的回退重做循环
- 进度可视化与状态同步
- 危险/不可逆步骤前的主动暂停（与安全规则协同）

**不包含：**

- 实际领域工作本身（写代码、分析、生成内容由具体技能或通用能力完成，本 skill 只管过程）
- 业务/投资等实质决策（只做流程编排，不做判断）
- 个人文件的销毁类高风险操作（遵循独立的安全规则，本 skill 不覆盖触发与执行逻辑）
- 单步或一眼能完成的简单任务（不强行里程碑化，避免啰嗦）
